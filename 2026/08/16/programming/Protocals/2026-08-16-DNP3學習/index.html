DNP3學習

因為本人最近在求職，對於相關工業協定有興趣，所以整理了一些筆記，方便自己複習，也希望對其他人有幫助。

DNP3 是什麼?

DNP3 的全名是 Distributed Network Protocol 3。

它主要被使用在以下場景：

  • 電力系統
  • 變電站自動化
  • 遠端終端設備 RTU
  • SCADA 監控系統

簡單來說，DNP3 就是一套專門給工業控制與電力監控使用的通訊協定，讓控制中心可以和遠端設備穩定交換資料。

它和 Modbus 一樣都屬於應用層協定，但 DNP3 在設計上更強調：

  • 不穩定通訊環境下的可靠傳輸
  • 事件回報
  • 時間戳記
  • 多層資料模型

例如控制中心會問：

  • 現在開關是不是跳脫了?
  • 目前量測到的電壓是多少?
  • 某個警報是什麼時間發生的?
  • 請你幫我把某個輸出接點打開

所以在需要監控大量遠端設備，而且還很在意事件先後順序的情境下，DNP3 通常會比 Modbus 更常被拿來使用。

這也表示 Modbus 主要是在取得即時性資料，而 DNP3 則是更偏向「事件導向、狀態變化紀錄與回報」的資料傳輸。

DNP3 資料形式?

DNP3 本質上是 Object-based protocol，線上傳輸的資料會用 Group + Variation 指定「這是什麼資料、用什麼格式編碼」。

DNP3 根據用途、型態會分以下：

用途：

  1. Static Data：靜態資料，例如開關狀態、量測值
  2. Event Data：事件資料，例如開關跳脫、警報觸發

型態(Object) 有很多這裡不一一列出：

  1. Binary Input / Output：二進位輸入/輸出，例如開關、繼電器
  2. Analog Input / Output：類比輸入/輸出，例如電壓、
  3. Counter：計數器，例如累計脈衝數、累計事件數
  4. Control：控制命令，例如開關操作、設定值變更

常見的資料型態

一個 DNP3 的訊息會是長這樣：

可以把它理解成：

  • Application Header： 我要做什麼
  • Object Header：我要對什麼資料做
  • Object Data：真正的資料內容

例如同樣是 Binary Input，可能會有：

  • 只有狀態值
  • 狀態值加上旗標
  • 狀態值加上時間戳記

這種設計的好處是它可以很清楚表達「同一種資料有哪些不同表現方式」。

所以在看 DNP3 文件時，常常會看到類似下面的概念：

  • Object 1：Binary Input (意思就是第 1 個物件類別是 Binary Input)
  • Object 30：Analog Input
  • Object 20：Counter

至於每個 Object 對應哪種 Variation，就要看規範與設備實作。

例如 Master 問 Outstation： 請給我 Analog Input #0~#2 的現在值

那就可以拆成：

  • 我要做什? → Read
  • 我要用甚麼種類資料? -> Analog Input
  • 我要用什麼格式? -> 32-bit integer + Flags
  • 我要那些Point? -> #0~#2

Double-Bit Binary Input

這個就是兩位元的開關狀態，例如某些設備可能有三種狀態：

  • 00 = Intermediate (中間狀態)
  • 01 = Determined OFF (確定關閉)
  • 10 = Determined ON (確定開啟)
  • 11 = Indeterminate (不確定)

為什麼會這樣? 這是因為某些設備例如 Breaker 不一定只有兩種狀態。有可能是正在切換中，或者因為通訊不穩定而無法確定狀態。

Analog Input

Analog Input 就是量測值，例如電壓、電流、溫度：

看到數值想當然就會有不同型別，例如：

  • 16-bit integer
  • 32-bit integer
  • 32-bit float
  • 64-bit double

這就是為甚麼 DNP3 會用 Object + Variation 來描述資料，因為同一個類別的資料可能有不同的表示方式。

例如：
Object 30 = Analog Input

  • Variation 1 = 16-bit integer
  • Variation 2 = 16-bit integer + flags
  • Variation 3 = 32-bit integer

為什麼 DNP3 很重視事件?

很多工控場景不只是想知道「現在值是多少」，而是更在意：

  • 什麼時候變了?
  • 哪個點先變?
  • 有沒有漏掉重要警報?

因此 DNP3 內建了 event-oriented 的概念。

例如某個開關在 10:01:05 跳脫，另一個警報在 10:01:07 發生，那系統除了知道最後狀態，也能根據時間戳記了解事件順序。

這對電力系統非常重要，因為故障分析常常就是在追查：

  • 是哪個保護先動作?
  • 是哪個斷路器先跳?
  • 是故障造成警報，還是警報觸發了後續動作?

Class 0 / 1 / 2 / 3 是什麼?

DNP3 會把資料或事件分成不同類別，最常見的是：

  • Class 0：目前靜態資料
  • Class 1：高優先事件
  • Class 2：中優先事件
  • Class 3：低優先事件

這樣 Master 就能依照需求安排輪詢策略。

例如：

  • 平常先頻繁讀取 Class 1 事件
  • 其次讀取 Class 2、Class 3
  • 偶爾再做一次 Class 0 完整掃描

這種方式比「每次都把所有資料全部重讀」更有效率，也更適合頻寬有限的環境。

DNP3 可以跑在哪些傳輸方式上?

DNP3 本身是應用層協定，底層可以跑在不同媒介上，常見的是：

  • Serial
  • TCP/IP

所以你會看到：

  • DNP3 Serial
  • DNP3 over TCP

如果走 TCP/IP，概念上就像：

Layer Protocol
7 DNP3
4 TCP
3 IP
2 Ethernet

但如果走 Serial，就會搭配串列傳輸的資料鏈路層格式。

DNP3 跟 Modbus 差在哪?

參考以下表：

比較項目 Modbus DNP3
常見場景 一般工業設備通訊 電力、SCADA、遠端監控
資料抽象 偏寄存器導向 偏物件導向
事件機制 較弱 很強
時間戳記 通常需額外設計 原生支援較完整
適合環境 簡單、直接 複雜、遠端、需高可靠性

所以你可以粗略理解成：

  • Modbus 比較像「我要去讀某個位址的資料」
  • DNP3 比較像「我要取得某種類型的設備狀態與事件」

兩者都很常見，只是適合的應用情境不太一樣。

Unsolicited Response 是什麼?

一般協定常常是 Master 問了，設備才回。

但 DNP3 支援 Unsolicited Response，意思是 Outstation 在特定事件發生時，可以主動送資料給 Master，而不必等主站先問。

例如：

  • 某個保護裝置跳脫
  • 某個重要警報被觸發
  • 某個類比值超過門檻

這樣的好處是反應更快，也能減少主站一直高頻率輪詢所有點位的負擔。

為什麼設備可以主動通訊？

這是因為通訊仍然是用 Serial 或 TCP/IP 的連線，這些連線本身就是可以雙向傳輸的。

時間同步為什麼重要?

既然 DNP3 很重視事件順序，那時間同步就很重要。

如果不同設備的時間不一致，就可能出現：

  • 事件先後順序判斷錯誤
  • 故障分析困難
  • 歷史紀錄失真

因此在實務上，DNP3 系統常常會搭配時間同步機制，讓 Outstation 回報的事件時間盡量準確。

Secure Authentication 是什麼?

早期工業協定很多都不是以資安為主要出發點，DNP3 也一樣。

因此後來延伸出 DNP3 Secure Authentication，目的是避免未授權控制命令被任意偽造或重放。

這代表如果系統要上線到更大範圍網路，甚至跨站點傳輸，就不能只看功能有沒有通，還要考慮：

  • 身分驗證
  • 命令完整性
  • 重放攻擊防護

也就是說，工控協定不能只看「能不能收發資料」，還要看「是不是安全地收發資料」。

感覺 DNP3 比 Modbus 複雜很多? 為什麼部全部更換成 DNP3?

這是因為 DNP3 和 Modbus 本來就服務不同層級與需求。
對只需要簡單 current-state polling 的設備來說，Modbus 的低複雜度反而是優點；DNP3 的 Event、Timestamp、Quality、Buffer 等能力主要在遠端 SCADA 與高可靠度監控環境才真正有價值。
因此實務上常見的不是 DNP3 取代 Modbus，而是 Gateway 同時整合兩者。
