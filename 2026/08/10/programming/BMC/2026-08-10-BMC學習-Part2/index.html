查詢系統裡有哪些感測器數值

這個指令是透過 D-Bus 向 OpenBMC 的 Object Mapper 查詢：「系統裡哪些物件是感測器數值？」

D-Bus 是一個在 Linux 系統中用來讓不同程式之間溝通的機制，OpenBMC 使用 D-Bus 來管理系統中的各種資源和服務。Object Mapper 是 OpenBMC 的一個服務，它負責管理系統中的物件和它們的介面。

可以把這個指令拆開來看：

Part Description
busctl call 呼叫 D-Bus 的指令
xyz.openbmc_project.ObjectMapper 要呼叫的服務名稱
/xyz/openbmc_project/object_mapper 要呼叫的服務的 object path
xyz.openbmc_project.ObjectMapper 要使用的介面名稱
GetSubTreePaths 要呼叫的函式名稱
sias 參數型別：s 字串、i 整數、as 字串陣列
/ 從 D-Bus 根目錄開始找
0 搜尋深度 0，代表不限深度
1 xyz.openbmc_project.Sensor.Value 要求介面陣列有 1 個項目，且必須包含這個感測器數值介面

輸出會類似以下，表示系統裡有四個感測器數值物件：

  • /xyz/openbmc_project/sensors/fan_tach/fan0
  • /xyz/openbmc_project/sensors/fan_tach/fan1
  • /xyz/openbmc_project/sensors/fan_tach/fan2
  • /xyz/openbmc_project/sensors/voltage/vbat

這裡開始會與 Arduino/Raspberry Pi 等的感測器操作有些不同，因為 BMC 的感測器數值是透過 D-Bus 來查詢的，而不是直接透過 GPIO 或 I2C 來讀取。

Arduino： 溫度感測器 → 你的 .ino 程式 → Serial 印出溫度

OpenBMC 溫度感測器 → Linux driver → hwmon/sysfs → sensor service → D-Bus → Web UI / Redfish / IPMI / 其他服務

所以接下來我們應該先拆解一個既有 sensor，例如 vbat。查出哪個 service 擁有它
