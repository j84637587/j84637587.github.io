本人最近在求職，想要玩 BMC 相關職涯領域發展，但以前只有嵌入式的知識，所以嘗試學習，並同步整理筆記，方便自己記錄學習，也希望對其他人有幫助。

延續上篇 Part2，我們已經知道 BMC 的感測器資料會透過 D-Bus 以物件與屬性的方式被暴露出來。

我們確定了 Romulus QEMU image 有風扇、電壓 sensor，但沒有可直接拿來練的溫度 sensor。所以先建立一個可控的虛擬溫度來源，就能確定：

自訂 service 能啟動 → 能正確擁有 D-Bus 名稱與 object path → 能發布標準 Sensor.Value → OpenBMC 的其他服務能找到它

詳細如下：

  1. 自訂 service 能啟動
    systemd 開機後自動執行 virtual-temp-service

  2. 擁有 D-Bus 名稱與 object path
    在系統中登記：
    service：xyz.openbmc_project.VirtualSensor
    path：/xyz/openbmc_project/sensors/temperature/virtual_temp

  3. 發布標準 Sensor.Value
    在這個 path 上提供：
    Value = 21500
    Unit = DegreesC

  4. 其他服務能找到它
    Web UI、Redfish、告警、風扇控制等
    不必知道你的程式檔名，只要找標準感測器介面即可取得數值。

建立 Yocto recipe

首先知道一下 Yocto 是甚麼，Yocto 是一個開源專案，提供了一個靈活的建置系統，用於創建嵌入式 Linux 系統的映像檔。它使用 BitBake 作為建置工具。

簡單來說就是把相關程式打包成 image 的工具。

  • Yocto recipe 是一個描述如何建置軟體包的檔案。每個 recipe 通常對應一個軟體包，定義了該軟體包的來源、依賴關係、建置步驟以及安裝步驟。
  • Yocto layer 是一組和某個功能有關的建置規則與檔案的資料夾。是在 recipes 之上的一個抽象層，通常包含多個 recipes、配置檔案以及其他資源。透過 layer，可以將不同的功能模組化，方便管理與重用。
