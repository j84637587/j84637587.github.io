    2026-08-02-RTOS複習 Part3

    發表於 2026-08-02 更新於 2026-08-25

    因為本人最近在求職，需要複習相關RTOS知識，所以整理了一些筆記，方便自己複習，也希望對其他人有幫助。

    延續上篇 (Part2)，我們在上篇文章作了以下事情，接著將進一步去做延伸。

    Part2：

    • 用 miscdevice 建立 /dev/virtual_sensor
    • 實作 read()，讓 cat /dev/virtual_sensor 讀到溫度資料
    • 提供 Makefile 與交叉編譯指令
    • 將 .ko 模組打包進 Buildroot image
    • 說明 insmod、dmesg、rmmod 的載入、測試與卸載流程
    • 進階版加入 atomic_t 和 kernel timer，讓溫度在 21.0°C～22.0°C 間每秒變動
    • 以 watch -n 1 cat /dev/virtual_sensor 觀察溫度變化

    目標

    根據 Part2 的內容，可以注意到幾件事情：

    1. 更新頻率固定、寫死的、不靈活
    2. 只能讀取
    3. cat /dev/virtual_sensor 只能讀溫度
    4. 溫度由 timer 更新，但沒有設定介面
    5. 沒有同步保護

    為了解決這些問題，本 Part 將做以下延伸：

    1. update_interval_ms 可設定，預設 1000 ms
    2. 多了 .unlocked_ioctl
    3. user-space 程式可透過 ioctl() 設定更新間隔
    4. 多了 virtual_sensor_ioctl() 接收設定命令
    5. 加了 spinlock 保護溫度、方向與更新間隔

    程式碼

    新增 virtual_sensor_ioctl.h，內容如下：

    • VIRTUAL_SENSOR_IOCTL_MAGIC 這是用來識別這個 driver 的 ioctl 命令群組的識別字, 變數可以任意命名. 但值要唯一。
    • ioctl 是 Linux 中對裝置下控制命令的系統呼叫，全名是 input/output control
      • 一般檔案常用 read, write, open, close 等系統呼叫，但對於裝置而言，這些系統呼叫可能不足以控制裝置的行為，因此 ioctl 提供了一個通用的介面，讓使用者程式可以傳遞控制命令給裝置驅動程式。
    • VIRTUAL_SENSOR_SET_INTERVAL_MS 是在定義一個設定更新間隔的 ioctl 命令編號：
      • _IOW 是用來定義一個 ioctl 命令的巨集，表示這個命令是從 user space 寫入資料到 kernel space，並且傳遞的資料型別是 unsigned int。
        • 是在定義 virtual sensor 的命令群組 第 1 個命令 user space 傳一個 unsigned int 給 kernel
        • 參數
          • VIRTUAL_SENSOR_IOCTL_MAGIC：命令群組識別字
          • 1：命令編號，這裡是第 1 個命令
          • unsigned int：傳遞的資料型別

    執行後會產生一個 virtual_sensor.ko 的檔案，是 Kernel Object ，這就是我們的 kernel module。

    • 和一般程式的差異： .c → 編譯＋連結 → ELF 執行檔 → Linux 用 ./program 啟動成一個行程
