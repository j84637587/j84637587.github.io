Modbus學習

因為本人最近在求職，對於相關工業協定有興趣，所以整理了一些筆記，方便自己複習，也希望對其他人有幫助。

Modbus 到底是什麼?

簡單來講，他就是一套工業通訊協定，主要用於工業自動化系統中設備之間的資料傳輸。

他最主要工作是去定義說：

  • 我要讀哪個設備的哪一筆資料?
  • 我要寫哪個暫存器?
  • 這個命令代表什麼?

例如： Client/Master 端想要讀取 Server/Slave 端的溫度值，他會發送一個讀取命令，指定要讀取的暫存器地址。

  • Client/Master 要怎麼知道要讀取的暫存器地址是什麼? 這就要看設備的規格書，通常會有一個表格列出每個暫存器的功能與地址。

所以這個協定就是在規定

  • 我要做什麼?
  • 讀哪裡?
  • 讀多少?
  • 寫什麼?

所以這樣看來 Modbus 其實是走在 Layer 7 的應用層協定，主要是定義資料的格式與傳輸方式。就好比 HTTP, FTP, DNS 這些協定一樣，都是在應用層去定義資料的格式與傳輸方式。

Modbus 資料形式?

Modbus 最常看到四種資料，稱作功能碼，可以當作遊戲中的 Op Code。

功能碼 類型 名稱 讀寫 資料大小
0x01 Coil 線圈 Read / Write 1 bit
0x02 Discrete Input 離散輸入 Read Only 1 bit
0x03 Input Register 輸入暫存器 Read Only 16 bit
0x04 Holding Register 保持暫存器 Read / Write 16 bit

假設有一個機器，它包含馬達、按鈕開關、溫度感測器。
根據資料可以得出以下的表。

類型 功能 數值
Coil 馬達啟動/停止 0/1
Discrete Input 按鈕開關狀態 0/1
Input Register 溫度感測器數值 16 bit 整數
Holding Register 馬達轉速設定值 16 bit 整數

所以像是 “Read Holding Registers”(這只是示意) 這個命令意思就是 “我要讀取設備裡的一組 16-bit Holding Register”。

Client / Master 怎麼知道要讀哪個暫存器？

通常 Client / Master 端會依據設備的規格書來決定要讀取哪個暫存器。規格書會列出每個暫存器的地址、功能以及資料類型。而規格書稱作 “Modbus Register Map”。

所以 Modbus 協定本身並不會告訴你要讀哪個暫存器，這是由設備的設計者決定的。

Modbus RTU/ASCII/TCP/UDP 是甚麼?

Modbus 常常不會單獨出現會看到 Modbus RTU、Modbus ASCII、Modbus TCP 這些名詞。

剛才有提到 Modbus 是 Layer 7 的應用層協定，因此這邊的 RTU、ASCII、TCP 其實是 Layer 2/3/4 的傳輸層協定。

Modbus RTU(Remote Terminal Unit)

Modbus RTU 是 Modbus 的一種傳輸方式，使用二進位格式傳輸資料，通常用於串列通訊（RS-232、RS-485）。

RS-232 電腦主機就看得到，在舊版的螢幕會使用的 Com Port (主要用來快速傳輸大量資料)。
RS-485 相較 RS-232 更適合長距離傳輸，且可以 1vN 通訊。

封包結構長這樣：

  • Address：設備地址，1 byte，範圍 0~247
  • Function Code：功能碼，1 byte，範圍 1~255
  • Data：資料，長度不固定，依功能碼而定
  • CRC：循環冗餘檢查，2 byte，用來檢查資料是否正確
Address Function Code Data CRC
1 Byte 1 Byte n 2 Byte

你可以注意到 Address 只有 1 byte，範圍 0~247。

但在 Register 中，地址通常是 16 bit，例如 40001。所以實際傳送的 Address 會是 zero-based offset，也就是從 0 開始計數。

Modbus ASCII

Modbus ASCII 是 Modbus 的另一種傳輸方式，使用 ASCII 字元格式傳輸資料，通常用於串列通訊（RS-232、RS-485）。

所以 Modbus ASCII 跟 Modbus RTU 很像，最大的不同就是資料傳輸的格式不同，ASCII 是用文字表示，RTU 是用二進位表示。

阿想當然 String vs Binary 資料量差距很大，所以 Modbus ASCII 的傳輸效率會比 Modbus RTU 低很多。

Modbus TCP(Transmission Control Protocol)

Modbus TCP 是 Modbus 的一種傳輸方式，使用 TCP/IP 協定在網路上傳輸資料，通常用於以太網通訊。

所以注意這裡的 Modbus TCP = Modbus + TCP/IP。

所以完整分層會是這樣：

走的是網路協議。

Layer Protocol
7 Modbus
4 TCP
3 IP
2 Ethernet

所以前面的 “Read Holding Registers” 在這邊，其實只是把 Modbus 的資料包裝在 TCP/IP 的封包裡面傳輸。

Modbus Request -> TCP -> TCP Segment -> IP -> IP Packet -> Ethernet Frame -> Ethernet

封包結構長這樣：

  • Transaction Identifier：交易識別碼，2 byte，用來識別請求與回應的對應關係
  • Function Code：功能碼，1 byte，範圍 1~255
  • Data：資料，長度不固定，依功能碼而定
MBAP Header Function Code Data
7 Bytes 1 Byte n

與 RTU 的差別在於：

  1. 沒有 Address，因為 TCP/IP 已經有 IP Address 了
  2. 多了 MBAP Header，用來識別請求與回應的對應關係
  3. 沒有 CRC，因為 TCP/IP 已經有檢查機制了
    • 所以常常會見到的是用 TCP 而不是 UDP，因為 TCP 有可靠傳輸的機制，UDP 沒有。

MBAP Header (Modbus Application Protocol Header)：

MBAP Header 長這樣：

  • Transaction Identifier：交易識別碼，2 byte，用來識別請求與回應的對應關係
  • Protocol Identifier：協定識別碼，2 byte，固定為 0x000
  • Length：長度，2 byte，表示後面資料的長度
  • Unit Identifier：單位識別碼，1 byte，用來識別設備，通常用於 Modbus TCP to Modbus RTU 的橋接器
Transaction Identifier Protocol Identifier Length Unit Identifier
2 Bytes 2 Bytes 2 Bytes 1 Byte

其中 Transaction Identifier 用來辨識是哪個請求的對應回應。
